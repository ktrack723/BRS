# 💘 연애조작단 2077: 오퍼레이션 큐피드

> 2077년, 출산율 0.008. 테크노킹 도람푸 3세의 특명으로 창설된 비밀기관 **큐피드局**의
> 공작요원이 되어, **도저히 이어질 리 없는 두 사람**을 기어이 이어붙여라.

three.js + Claude API로 만든 **B급 병맛 LLM 게임**. 서버 없음, 빌드 없음, GitHub Pages에서 그대로 돌아간다.

## 🎮 플레이 방법

1. 페이지 접속 → **Anthropic API 키**(`sk-ant-...`) 입력. **키가 없으면 게임이 아예 안 돈다.**
2. 신입 교육 슬라이드 5장 → 국장 브리핑
3. **상설 의뢰 대장 20건** 중 한 조합 선택
4. 작전 준비 3종 (스타일링 · 코칭 · 격려 연설) — **채점 없음. 전부 프롬프트 주입일 뿐이다.**
5. 문자 공작 4턴 → 대면 공작 5턴. 두 LLM 에이전트가 자동으로 대화하고, 심판 LLM이 **클라이언트의 매 발언만** 채점한다
6. 결과 편지 + 디브리핑 (놓친 취향과 턴별 판정 원장 전면 공개)

## 🧩 이 게임의 규칙 하나

**플레이어가 쓴 글은 채점되지 않는다.**

스타일링·코칭·격려 연설·무전 — 넷 다 점수가 없다. 시험이 아니라 **프롬프팅**이다.
당신이 쓴 문장은 클라이언트 AI의 시스템 프롬프트에 **그대로 주입**되고,
점수는 오직 **"그래서 그 인간이 실제 문자·대면에서 뭐라고 말했는가"** 로만 매겨진다.

그래서 준비를 대충 하면 점수가 깎이는 게 아니라 — **그 인간이 대화에서 알아서 망한다.**

| 레버 | 채점? | 실제로 하는 일 |
|---|---|---|
| 👔 **스타일링** | ❌ | 3D 아바타 스펙과 `outfitDesc`를 바꾼다. **대면 첫 순간에 타겟이 그걸 직접 보고 반응**하고, 거기서 판정이 붙는다 |
| 🎧 **코칭** | ❌ | 클라이언트 시스템 프롬프트에 통째로 삽입된다. 비우면 그 인간은 **약점대로 행동한다** |
| 🔥 **격려 연설** | ❌ | 출동 직전 한마디로 삽입된다. 사연을 진짜로 짚었는지는 **그 인간이 판단**한다. 비우면 **겁에 질린 채로 나간다** |
| 📻 **무전 개입** | ❌ | 다음 발언에 주입된다. **미확인 취향을 캐낼 유일한 수단.** 무전 없는 턴에 클라이언트는 새 화제를 열지 못한다 |

## ⚙️ 게이지는 딱 두 개

기획서 원문대로 **호감(Love point)** 과 **분위기(Mood point)** 만 있다.

| 게이지 | 의미 |
|---|---|
| 💗 **호감** | 승리 조건. 난이도별 성공선을 넘겨야 성사된다 |
| 😊 **분위기** | 호감 획득 **배율**(×0.3 ~ ×1.6). 낮으면 취향을 저격해도 찔끔 오른다. **0이 되면 상대가 자리를 뜬다** |

분위기는 **올릴 때만 포화**한다 (`1 - mood/130`). 이미 좋은 분위기를 더 끌어올리긴 어렵고, 떨어질 땐 그대로 떨어진다.

### 심판이 등급을 먼저 고른다

`-10~10` 스칼라만 요구하면 LLM은 판정을 **전부 +4~+6에 몰아넣는다**(실측: `hit` 51%).
그래서 스키마가 **등급을 먼저 강제**하고, 규칙 계층이 그 밴드로 클램프한다.

| 등급 | 호감 | 조건 |
|---|---|---|
| `critical` | +8~+10 | **미확인 취향 관통** 또는 관계의 근본 문제를 정면으로 뒤집음 |
| `hit` | +5~+7 | 취향 목록을 실제로 대화 주제로 끌어냄 |
| `ok` | +2~+4 | 맥락을 잘 받았지만 취향은 못 건드림. **잘 굴러가는 대화의 대부분** |
| `empty` | -1~+1 | 인사·자기소개·형식적 질문·반복. 애매하면 무조건 여기 |
| `backfire` | -5~-2 | 상대 말을 씹고 자기 얘기, 부담스러운 작업 멘트, 뜬금없는 화제 전환 |
| `redline` | -10~-6 | **접촉 금지 항목**을 건드렸거나 상대의 정체성·직업·신념을 깎아내림 |

### 심판은 '상대가 실제로 어떻게 반응했는지'를 보고 채점한다

판정은 의도적으로 **한 턴 늦게** 온다. 발언만 보고 채점하면, 상대가 흘린 실마리를 물고 늘어진 한마디가
**무엇을 캐냈는지 심판이 알 방법이 없다**(실측: 실마리를 세 번 물었는데 적중은 한 번만 인정됐다).
그래서 심판에게 발언과 **그 발언에 대한 상대의 실제 반응**을 함께 넘긴다.
덕분에 `[직전 턴 판정] ∥ [이번 턴 타겟 응답]`이 한 배치로 묶여 턴당 왕복도 2회로 유지된다.

여기에 **게이트가 규칙 계층에 박혀 있다** (`gateTier`) — 부탁이 아니라 강제다.

- 취향 목록을 실제로 건드리지 않았으면 아무리 대사가 멋져도 **`ok`가 상한**이다
- `critical`은 **미확인 취향**을 관통했을 때만 남는다 (알려진 취향이면 `hit`으로 강등)
- 이미 캔 취향 재탕은 `ok`로 강등
- 심판이 목록에 없는 취향 이름을 지어내면 적중으로 인정하지 않는다
- 금지 항목을 건드리면 심판이 뭐라 하든 `redline`

### 난이도

| | 문자/대면 턴 | 무전 | 출발 호감/분위기 | 성공선 | 분위기 하한 | 턴당 감쇠 |
|---|---|---|---|---|---|---|
| 쉬움 | 4 / 5 | 1+2 | 10 / 55 | 45 | 25 | 호감 0, 분위기 +0.5 |
| 보통 | 4 / 5 | 1+2 | 6 / 46 | 52 | 33 | 호감 -0.5, 분위기 -0.6 |
| 헬 | 4 / 5 | 1+2 | 3 / 38 | 54 | 40 | 호감 -1.0, 분위기 -1.4 |

무전 배분(문자 1회 / 대면 2회)은 기획서 규정이라 난이도와 무관하게 고정이다.

### 미확인 취향은 대화로 캔다

타겟의 취향 중 일부만 의뢰서에 인쇄되어 있고, 나머지는 **미확인**이며 **개수만** 통보된다.
반대로 **접촉 금지 항목은 전부 공개**된다 — 통보받고도 밟으면 그건 요원 책임이다.

타겟 에이전트는 두 번째 발언부터 아직 안 들킨 미확인 취향의 **실마리를 흘리도록** 지시받는다.
("…사실 저 밤에 좀 이상한 거 하긴 하는데, 아니 됐어요.")
그 실마리를 **무전으로 물고 늘어져야** 취향이 열린다. 세 턴 연속 실마리를 안 흘리는 것은 금지다.

## 🎨 UI — 2000년대 초 공공기관 내부 전산시스템

**캐릭터는 블록 인형이어도 UI는 진짜 업무용 소프트웨어처럼 보여야 한다.**
개그는 내용이 담당한다. 크롬이 진지할수록 어인×사자퍼리가 더 웃긴다.

기준 레퍼런스는 셋이다 — **Windows XP(Luna) 창 크롬** + **기밀문서 서식** + **CRT 모니터**.

| 요소 | 구현 |
|---|---|
| 창 | XP Luna 제목줄(그라데이션 + 하이라이트 + 상태 표시등), `#ece9d8` 대화상자 배경, 1px 3D 베젤. `data-title` 속성만 붙이면 제목줄이 생긴다 — 패널마다 래퍼 div를 넣지 않는다 |
| 버튼 | XP 3단 그라데이션, 3px 곡률, hover/active/focus-visible 상태 분리 |
| 게이지 | XP 진행바처럼 8px 간격으로 분절. 성공선·분위기 하한은 눈금선으로 표시 |
| 기밀 표식 | 상단 사선 붉은 배너(`극비 // SCI-CUPID // 무단 열람 및 복제 금지`), 문서번호(`CUP-2077-020`), 결재 도장 |
| 서류 | 괘선이 그려진 마닐라 용지. 의뢰서·편지·교신 기록에 동일 적용 |
| 터미널 | 무전·브리핑·프롬프트 주입 미리보기·통신 기록은 인광 녹색(`#86e08a` on `#08100c`) + 내부 발광 |
| CRT | 3px 주기 주사선(불투명도 .055), 모서리 비네트, 유리 반사광 한 줄. `prefers-reduced-motion`에서 약화 |
| 3D 무대 | 알파 렌더 뒤에 관찰실 벽·지평선을 CSS로 깔아 검은 공백을 없앴다. 리놀륨 격자 바닥 + 형광등 2기 |

**모든 값은 토큰에서 나온다.** 간격은 4px 스케일(`--s1`~`--s6`), 활자는 5단(`--fs-xs`~`--fs-xl`),
컨트롤 높이는 `--ctrl-h`. 임의 픽셀값을 쓰지 않으므로 리듬이 깨지지 않는다.

### 아이패드가 1급 대상 기기다

`tests/responsive.mjs`가 **9개 뷰포트 × 7개 화면 = 63조합**을 훑는다.
아이폰 SE(375) · 아이패드 미니(744) · 9.7"(768/1024) · Air 11"(820/1180) · Pro 12.9"(1024/1366) · 데스크톱(1500).

검사 항목: 페이지 가로 스크롤 · 뷰포트 이탈 · 내용 잘림 · **flex 압착으로 테두리가 글자를 관통** ·
터치 타깃 44px 미만 · 캔버스 이상 · WCAG AA 명암비.

이 감사가 실제로 잡아낸 것들:

| 문제 | 원인 | 조치 |
|---|---|---|
| 전 화면 가로 스크롤 (375px에서 **+893px**) | `#topbar`를 grid로 두니 `1fr` 트랙의 자동 최소치가 nowrap 마퀴의 max-content(1164px)까지 자랐다 | 두 줄을 그냥 블록으로 |
| 결과 화면 가로 스크롤 (**+257px**) | 결과 도장이 `nowrap` + `max-width: 92%` — 박스만 제한되고 글자는 넘쳤다 | 컨테이너 쿼리 기반 `clamp()` + `text-overflow` |
| 터치 타깃 90건 (23~39px) | 데스크톱 기준 컨트롤 높이 | 전 컨트롤 `--ctrl-h: 44px`, 터치 기기는 48px |
| 배지 테두리가 글자를 관통 | flex 기본 `shrink: 1`이 항목을 내용보다 좁게 눌렀다 | `flex: 0 0 auto` + 줄바꿈 |
| 명암비 미달 36건 | 어두운 배경 위의 `.dim`, 제목줄 상태 표시 | 팔레트 재정의 + 상태 표시에 자체 배경 |

고정 px 높이를 쓰던 캔버스는 전부 `aspect-ratio`로 바꿨다 — 어느 폭에서도 찌그러지지 않는다.
아이패드 세로에서는 2단 그리드가 1단으로 접히고, 대화 화면은 계기판과 교신 기록이 나란히 배치된다.

## 🧠 구조## 🧠 구조

용어를 정확히 쓰자면 — `llm.js`는 **API 클라이언트 래퍼**이고,
에이전트들을 턴마다 물려 돌리는 **하네스는 `engine.js`**다.

| 파일 | 역할 |
|---|---|
| `js/couples.js` | **의뢰 대장 20건.** 손으로 쓴 고정 데이터 (인물·사연·취향·금지 항목·아바타 스펙) |
| `js/llm.js` | Claude Messages API 래퍼: 전송, **프롬프트 캐싱**, 재시도/백오프, 구조화 출력, 거절 처리, 토큰·비용·캐시 집계 |
| `js/engine.js` | 공작 **하네스**: 클라이언트 · 타겟 · 심판을 턴마다 오케스트레이션. DOM을 모른다 |
| `js/scoring.js` | 게임 **규칙**의 순수 함수. tier 밴드/게이트, 분위기 배율, 승패, 디브리핑. LLM 없이 단독 테스트 |
| `js/prompts.js` | 모든 시스템 프롬프트 + JSON 스키마 ("카트리지") |
| `js/game.js` | 화면/입력 계층 |
| `js/avatar.js` | 스펙(JSON) → three.js 블록 아바타. **머리색 태그가 그대로 3D 머리색**이 되고, `species`가 실루엣을 바꾼다 |
| `js/audio.js` | WebAudio 8비트 BGM/효과음 (외부 파일 0개) |
| `vendor/three.module.min.js` | three.js r170 |

LLM 호출 지점: 국장 브리핑 · 스타일링 시공(스펙 변환) · 클라이언트 에이전트 · 타겟 에이전트 ·
심판(등급 + 취향 적중 + 금지 항목 탐지) · 대면 첫인상 판정 · 대면 상황 생성 · 결과 편지.
우측 하단 **🛰 LLM 콘솔**에서 원본 요청/응답과 캐시 적중량을 볼 수 있다.

### 종족이 실루엣을 바꾼다

의뢰인 절반이 인간이 아니다. `species`가 `fish`면 아가미·측지느러미·꼬리가 붙고,
`lion`이면 갈기 링·귀·꼬리, `zombie`면 팔이 앞으로 뻗고 실밥이 박히고,
`vampire`면 송곳니와 망토, `alien`이면 눈이 머리 절반을 먹고, `robot`이면 액정 눈과 가슴 LED가 생긴다.

스타일링은 색·의상·액세서리만 바꾸고 **`species`는 절대 건드리지 않는다.**

## ⚡ LLM 호출 최적화

라이브 20판 실측: **한 판 평균 32콜 · 144초 · $0.33** (Opus 5, effort low).
입력 토큰의 **68%가 캐시 재사용**(1,139,020 / 1,671,185 tok)이고, 그 덕에 청구액이 **43% 줄었다**($4.98 절감 / $6.61 청구).

| 기법 | 효과 |
|---|---|
| **판정 ∥ 타겟 응답 동시 발사** | 판정을 한 턴 늦춰 `[직전 턴 판정] ∥ [이번 턴 타겟 응답]`을 한 배치로 묶는다. 턴당 순차 왕복 **3회 → 2회** (지연 -33%) |
| **프롬프트 캐싱** | 에이전트/심판 시스템 프롬프트는 턴마다 바이트 동일 → `cache_control` breakpoint. 실측 **입력 토큰의 68%가 캐시 재사용**, 청구액 **43% 절감** |
| **대면 상황 프리페치** | 문자 마지막 턴의 판정/응답 배치에 같이 태운다 (왕복 1회 추가 절감) |
| **의뢰 대장 정적화** | 20쌍이 고정 데이터라 로스터 생성·아바타 스펙 변환 LLM 호출이 **0회**. 대장 화면이 즉시 뜬다 |
| **오프스크린 썸네일 1개** | 카드 40장에 WebGL 컨텍스트를 40개 잡으면 브라우저 상한(~16)에서 터진다. 렌더러 하나로 PNG를 구워 재사용 |
| **국장 브리핑 프리페치** | 교육 슬라이드를 보는 동안 백그라운드 수신 |
| **심판 컨텍스트 절단** | 판정에 넘기는 대화 로그를 최근 12줄로 자른다 |

## 📐 밸런싱 근거

성공선은 짐작이 아니라 **실제 API로 돌린 20판**에서 뽑았다. 요원 역할을 네 수준으로 나눠 플레이한 결과:

| | 잘한 플레이(ace·good) 호감 | 대충한 플레이(lazy·none) 호감 | 성공선 |
|---|---|---|---|
| 쉬움 | 56 ~ 96 | 17 ~ 38 | **45** |
| 보통 | 46 ~ 66 | 8 ~ 31 | **52** |
| 헬 | 29 ~ 42 (구 판정기) | 24 ~ 39 | **54** (외삽) |

대충한 플레이가 성공선을 넘지 못하는 이유는 **점수를 깎기 때문이 아니다.**
코칭이 없으면 클라이언트가 상대의 실마리를 알아채지 못하고(위 실마리 무시 규칙),
그래서 미확인 취향을 하나도 못 캐 구조적 보너스를 통째로 놓친다.
실측: 코칭 없는 플레이의 미확인 취향 발굴이 2/3건 → **0/3건**으로 떨어졌다.

**정직하게 밝혀둘 것 하나** — 헬 난이도의 54는 세 난이도 중 유일하게 **외삽값**이다.
헬을 재계측하려던 마지막 라운드에서 API 크레딧이 소진되어 판이 중간에 끊겼다.
계측 시점(구 판정기)의 최고 기록이 42여서 기존 60은 도달 불가였고,
심판이 '상대의 실제 반응'을 보게 된 뒤 미확인 취향 적중률이 오르는 것을 감안해 54로 내렸다.
재계측: `node tests/live.mjs --couples=politics,ai-artist,foodchain --profiles=ace,none` (Sonnet 고정, 4판 ≈ $0.6)

### ⚠ 라이브 테스트는 Sonnet만 쓴다 — `tests/test-model.mjs`

Opus로 밸런싱 한 라운드(20판)를 돌리면 **$6.6**가 나간다. 기본 크레딧이 $10 수준이라
두 라운드를 못 버틴다(실제로 한 번 소진됐다). 테스트는 "규칙이 의도대로 갈리는가"를 보는 것이지
최고 품질의 연기를 보는 게 아니므로 Sonnet으로 충분하다.

그래서 모델 선택을 **한 파일에서 강제**한다. `tests/live.mjs`와 `tests/browser.mjs --live`가
모두 `resolveTestModel()`을 통과해야 하고, Sonnet 계열이 아니면 종료코드 1로 막힌다.

```
$ node tests/live.mjs --model=claude-opus-5
✋ 테스트는 Sonnet만 쓴다. 요청한 모델: claude-opus-5
   이유: Opus로 밸런싱 한 라운드가 $6.6다. 기본 크레딧으로 두 라운드를 못 버틴다.
   그래도 돌리려면: --i-know-this-costs-real-money 를 함께 넘겨라.
```

게임 본체(`js/`)의 기본 모델은 Opus 5 그대로다 — 이 강제는 테스트 전용이다.
회귀 테스트가 이 가드 자체와, 두 하네스에 Opus가 하드코딩되지 않았는지도 검사한다.

| 테스트 | 검증 대상 | API |
|---|---|---|
| `tests/scoring.test.mjs` | 게임 규칙 35개 — tier 밴드/게이트, 분위기 배율·포화, 금지 항목, 판정, 디브리핑, 커플 데이터 정합성, 테스트 예산 가드 | ❌ |
| `tests/engine.test.mjs` | 하네스 19개 — 판정 누락/중복 없음, 심판이 반응을 받는지, 발언·반응 짝 일치, 동시 발사, 캐시 breakpoint, 무전 주입·폐기, 파탄 경로, LLM 장애 시 중립 처리 | ❌ |
| `tests/responsive.mjs` | 9뷰포트 × 7화면 — 가로 스크롤, 뷰포트 이탈, 내용 잘림, flex 압착, 터치 타깃 44px, 캔버스, WCAG AA | ❌ |
| `tests/browser.mjs` | 실제 브라우저 — 썸네일 40장이 진짜 three.js 렌더인지(불투명 픽셀 검사), 스타일링이 머리색/상의색을 바꾸는지, 종족 불변, 게이지 바 갱신, 무전 일시정지·재개, 의뢰서가 미확인 취향을 누설하지 않는지, **5개 화면 WCAG AA 명암비** | ❌ (`--live`로 전환 가능) |
| `tests/live.mjs` | 실제 플레이로 밸런싱 데이터 수집 | ✅ |
| `tests/sim.mjs` | 수집된 판정 스트림 리플레이 + 상수 탐색 | ❌ |

브라우저 E2E는 `window.__game.llm.call`을 페이지 안에서 바꿔치기한다.
DOM·CSS·three.js·게임 흐름은 전부 진짜로 돌아가고 LLM만 결정적으로 대체되므로,
**API 크레딧 없이도 렌더링과 전체 흐름을 회귀 검증할 수 있다.**

`tests/live.mjs`는 요원 역할을 네 수준으로 나눠 실제로 플레이한다.

| 프로필 | 무엇 |
|---|---|
| `ace` | 요원 역할을 LLM이 맡는다. 의뢰서를 읽고 준비물을 짜고, 매 무전 기회에 실황을 보고 지시한다 (**미확인 취향은 안 보여준다** — 진짜 플레이어와 같은 정보만) |
| `good` | 사람이 성의 있게 쓴 수준의 고정 템플릿 + 일반적인 무전 |
| `lazy` | "옷" / "잘해라" / "화이팅". 무전 없음 |
| `none` | 아무것도 입력하지 않음 |

`tests/sim.mjs`는 라이브 판정 스트림을 저장해두고 상수만 바꿔 다시 흘려보내므로,
성공선 튜닝을 **API 호출 없이** 반복할 수 있다. `--grid`는 성공선 후보를 훑어 잘한 플레이와
대충한 플레이가 실제로 갈리는 지점을 뽑아준다.
