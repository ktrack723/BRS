# 💘 Ministry of Love

> 2077년, 출산율 0.008. 테크노킹 도람푸 3세의 특명으로 창설된 비밀기관 **L 기관**의
> 공작요원이 되어, **도저히 이어질 리 없는 두 사람**을 기어이 이어붙여라.
> (기관 이름은 어디서나 「L 기관」이다 — 프롬프트 안에서도, 인물들 입에서도.)

three.js + LLM API로 만든 **B급 병맛 LLM 게임**. 서버 없음, 빌드 없음, GitHub Pages에서 그대로 돌아간다.
키는 **Anthropic · OpenAI · OpenRouter** 셋 다 받는다. 업자를 고르는 화면은 없다 — 키를 보고 알아서 판별한다.

---

## 📐 이 게임의 설계도

이 저장소는 **한 장의 구조도**를 그대로 구현한 것이다. 그 그림에 없는 것은 게임에 없다.

![프롬프트 하이어아키](docs/prompt-hierarchy.jpg)

### 범례 — 색이 곧 데이터의 출처다

| 색 | 뜻 | 예 |
|---|---|---|
| 🟩 **static** | 테이블로부터의 Static 데이터 | 타겟 외모·성격·성장환경·취향 / 고객 성장환경 |
| 🟦 **user** | 유저 인풋 (모두 캐시됨) | 스타일링 · 동기부여 · 코칭 · 무전 · 현장 무전 |
| 🟫 **cached** | 캐시되는 LLM 생성 텍스트 | 수정된 고객 외모 & 성격 |
| 🟧 **once** | 일회성 LLM 생성 텍스트 | 고객 - 타겟 대화 · 후일담 텍스트 |
| ⬛ **code** | 코드용 분류 | 무드 포인트 · 러브 포인트 · 성사 여부 |

화면도 같은 색을 쓴다(`css/style.css`의 `--tone-*`). 어느 화면에서든 파란 칩은 「당신이 쓴 것」,
갈색 칩은 「캐시된 LLM 산출물」이다.

### 블록은 넷뿐이다

`A`는 상자 하나지만 **호출은 둘**이다. 상자가 직접 그어놓은 선(스타일링→외모, 동기부여→성격)에서
그대로 자른 것이라 흘러가는 데이터는 그림과 같다. 미용실은 성격을 못 보고, 취조실은 외모를 못 본다.

```
A-1. 미용실 — 스타일링
     [user]   스타일링 내용
   + [static] 고객 외모
   → [cached] 수정된 고객 외모   (+ 3D 조형)

A-2. 취조실 — 동기부여
     [user]   동기부여 내용
   + [static] 고객 성격
   → [cached] 수정된 고객 성격

S. 스크리닝 시 노출 정보              (프롬프트가 아니라 화면)
     [static] 타겟 외모 · 성격 · 성장환경 · 취향
   + [static] 고객 외모 · 성격 · 성장환경

B-1. 텍스팅 & 토킹 — 대사 생성      **배우 둘. 회선이 갈려 있다. 호출은 한 줄에 하나**

  ├ 고객 배우
  │    [cached] 고객 외모(스타일링됨) · 고객 성격(동기부여됨)
  │  + [static] 고객 성장환경 · 고객 말투
  │  + [user]   코칭 내용
  │  + [user]   무전 내용        ← 페이즈마다 한 번. 고객 회선에만 실린다
  │  + [user]   현장 무전 내용    ← 판 전체 한 번. 양쪽 회선에 실린다
  │  + [slip]   타겟 이름 · 나이 · 성별 · 직업   ← 통지서 한 줄. 이게 전부다
  │  → [once]   고객의 다음 대사 한 줄
  │
  └ 타겟 배우
       [static] 타겟 외모 · 성격 · 성장환경 · 취향(간직 항목 분리) · 타겟 말투
     + [user]   현장 무전 내용
     + [slip]   고객 이름 · 나이 · 성별 · 직업   ← 통지서 한 줄
     + [see]    고객 외모(스타일링됨)            ← **토킹 페이즈에만.** 그때 처음 본다
     → [once]   타겟의 다음 대사 한 줄

B-2. 텍스팅 & 토킹 — 판정
     [once]   고객 - 타겟 대화
   + [cached] 고객 외모(스타일링됨)
   + [static] 타겟 외모 · 성격 · 성장환경 · 취향
   → [code]   무드 포인트 증감 여부 · 러브 포인트 증감 여부

C. 후일담 생성
     [code]   러브 포인트
   + [once]   고객 - 타겟 대화
   + [cached] 고객 성격(동기부여됨)
   + [static] 타겟 성격
   → [code]   성사 여부      + [once] 후일담 텍스트
```

구조도에 없던 칸이 둘 늘었다 — 🟦 **무전**과 🟦 **현장 무전**이다. 코칭과 같은 색(유저
인풋)이고, 들어가는 **때**가 다르다. 코칭은 자리에 앉기 전에 한 덩이로 가고, 둘은 자리가
굴러가는 도중에 꽂힌다. 받는 쪽이 다르다 —

| | 받는 쪽 | 배급 | 하는 일 |
|---|---|---|---|
| 📻 **무전** | 고객의 귀 | 페이즈마다 1회 | **명령.** 고객이 다음 대사부터 반드시 이행한다 |
| 🚚 **현장 무전** | 현장 요원 | **판 전체 1회** | **물리 지원.** 거대 꽃다발이 도착하고 롤스로이스가 창밖에 선다 — 적은 그대로 실제로 벌어진다 |

현장 무전은 **물건을 놓지 마음을 놓지 않는다.** 사건은 그대로 실행되지만 두 사람이 그걸
어떻게 받아들이는지는 각자의 시트가 정한다 — 감탄일 수도, 의심일 수도, "누가 계산하는
거냐"일 수도 있다. 누가 시켰는지는 아무도 모르고, 심판은 이 문장을 보지 못한다 — 채점되는
것은 두 사람이 입 밖에 낸 반응뿐이다. 그것 말고는 구조도 그대로다.

### 두 배우는 서로의 시트를 못 본다

대사는 **한 줄에 한 번씩** 생성된다. 고객 배우와 타겟 배우가 번갈아 한 마디씩 쓰고, 서로의
프롬프트는 완전히 다르다. 고객 쪽 컨텍스트에는 **타겟의 성격도 성장환경도 취향도 간직 항목도
한 글자가 없고**, 타겟 쪽에는 고객의 성격도 코칭도 없다. 서로에 대해 아는 것은 셋뿐이다 —

1. L 기관이 보낸 **매칭 통지서 한 줄** (이름 · 나이 · 성별 · 직업. 사진 없음)
2. 지금까지 **실제로 오간 말**
3. 지금 **눈에 보이는 것** (텍스팅에선 아무것도, 토킹에선 상대의 외모)

옛 구조는 한 호출이 양쪽 대사를 다 썼다. 그때는 「상대 시트는 안 보이는 것으로 하라」는
**지시로만** 막고 있었고, 히든 성향이 대화로 새는 것을 구조가 막아주지 못했다. 지금은
애초에 컨텍스트에 없다 — **못 보는 것은 못 쓴다.**

값은 호출 수다: 구간 하나에 대사 6콜 + 판정 1콜. 대신 잘라낼 것이 없어졌다 —
무전이 들어오면 아직 쓰지도 않은 다음 줄에 그대로 실리므로, 버리는 대사도 재판정도 없다.

**이 표가 곧 회귀 테스트다.** `tests/orders.test.mjs`는 필드마다 표식을 심어 네 프롬프트를 만들고,
그 표식이 들어가야 할 곳에 들어갔는지 · **들어가면 안 되는 곳에 안 들어갔는지**를 전수로 확인한다.
`npm run audit`은 같은 규칙이 코드에 살아 있는지를 본다.

### 그리고 데이터가 아닌 것 하나 — R. 반응

```
R. 준비 단계 반응                      (구조도 밖. 데이터가 아니라 소리다)
     [user]   방금 내린 주문 하나 (스타일링 / 동기부여 / 코칭 중 하나)
   + [static] 고객 외모 · 성격 · 성장환경   ← 테이블 값. 시공되기 **전**의 것이다
   → [once]   그 자리에서 고객 입에서 나온 한두 마디
```

요원이 주문을 하나 내릴 때마다 고객이 대꾸한다 — *"정말 이걸 하라고요?"* 쪽이든, 잠자코
받아들이든. **이 문장은 화면에 뜨고 거기서 끝난다.** 대화도 판정도 후일담도 이걸 보지 못하고,
점수에도 닿지 않는다. 그래서 하이어아키를 건드리지 않는다 — 위 네 블록의 입력은 하나도 안 바뀐다.
`tests/orders.test.mjs`가 이것도 전수로 지킨다 (타겟을 못 본다 · 시공된 시트를 못 본다 ·
다른 방의 주문을 못 본다).

### 지시는 영어, 출력은 한국어

프롬프트의 **지시문은 전부 영어**다. 한국어는 셋뿐이다 — 테이블에서 온 인물 데이터,
화면에 그대로 뜨는 라벨, 한국어로 나와야 하는 출력의 예시. ASCII로만 된 가상 인물로 다섯
프롬프트를 지어 **한글이 한 글자라도 남으면 테스트가 깨진다.**

전수조사한 결과 지시문 쪽에 남은 한글은 없다. 나가는 프롬프트에서 한국어인 것은 둘뿐이고
둘 다 데이터다 — 인물 시트(`js/couples.js`)와 커플별 말투 표본(`js/voices.js`). 말투는
「존댓말인데 심문조」처럼 **한국어 어미·호칭을 지정하는 표본**이라 영어로 옮기면 지정하려던
것이 사라진다. 그래서 테이블에 남긴다.

## 🎮 플레이 방법

1. **부팅** — 요원명 + API 키. Anthropic(`sk-ant-...`) · OpenAI(`sk-...`) · OpenRouter(`sk-or-...`) 아무거나.
   **키가 없으면 게임이 아예 안 돈다.** 요원명은 서식 인쇄용이고 연산에는 넘어가지 않는다.
2. **신입 교육 슬라이드 4장** — 한 장에 한 줄, 한 장에 그림 하나. 첫 판을 시작하는 데 필요한 것만 남겼다
   (누구인가 · 무엇을 쓰는가 · 도중에 무엇을 할 수 있는가 · 두 게이지가 무엇인가). 화면에서 곧 보게 될 것은 설명하지 않는다.
3. **S · 스크리닝** — 상설 의뢰 47건. 각 건에 대해 **일곱 항목이 전부 열린다.**
4. **A-1 · 미용실** — 한 문장으로 고객의 **외모**를 통째로 덮어쓴다. 3D 아바타가 그 자리에서 바뀐다.
5. **A-2 · 취조실** — 형광등 하나, 의자 하나. 고객의 **성격**을 통째로 덮어쓴다. 외모는 여기서 안 건드린다.
6. **B · 코칭 하달** — 대화에서 뭘 하고 뭘 하지 말지, **고객에게만** 들어가는 명령 한 덩이.
   대화 장면 자체가 아니다 — 대화는 다음 단계에서 생성된다.
7. **B · 텍스팅 4구간 → 토킹 5구간** — 대화가 굴러가고, 매 구간 무드·러브가 오르내린다.
   굴러가는 도중에 **📻 무전**(텍스팅 1회 · 토킹 1회)과 **🚚 현장 무전**(판 전체 1회)을 때릴 수 있다.
8. **C · 후일담** — 성사 여부와 후일담.

준비 세 화면은 주문을 받을 때마다 고객의 반응을 한 줄씩 받아온다. 채점이 아니라 **소리**다.

## 🧨 이 게임의 규칙

### ① 요원이 쓴 글은 채점되지 않는다

손댈 수 있는 건 다섯뿐이다 — **스타일링 · 동기부여 · 코칭 · 무전 · 현장 무전.** 다섯 다 점수가 없다.
시험이 아니라 **프롬프팅**이다. 당신이 쓴 문장은 프롬프트에 **그대로 주입**되고,
점수는 오직 **"그래서 그 두 사람이 실제로 뭐라고 말했는가"** 로만 매겨진다.

| 레버 | 언제 | 채점? | 실제로 하는 일 |
|---|---|---|---|
| ✂️ **스타일링** (미용실) | 출격 전 | ❌ | 고객 **외모** 시트를 통째로 다시 쓴다. 3D 아바타도 같이 바뀐다 |
| 🔥 **동기부여** (취조실) | 출격 전 | ❌ | 고객 **성격** 시트를 통째로 다시 쓴다. 어떤 인간으로 그 자리에 앉을지가 여기서 정해진다 |
| 🎧 **코칭** (코칭실) | 출격 전 | ❌ | 대화 프롬프트의 고객 쪽에 **명령**으로 박힌다. 비우면 고객은 준비 없이 제 시트대로만 움직인다 |
| 📻 **무전** (판 도중) | 자리에서 | ❌ | 대화를 세우고 고객 이어폰에 명령을 꽂는다. **페이즈마다 한 번** |

심판은 **코칭도 무전도 못 본다.** 지시문이 보이면 심판은 두 사람이 실제로 한 말 대신 지시의
영리함을 채점하게 된다. 심판이 받는 고객 쪽 정보는 **스타일링된 외모 한 줄**뿐이다 — 타겟의
눈에 실제로 보이는 것이 그것뿐이기 때문이다.

### ② 감춰둔 항목은 없다

일곱 항목이 스크리닝에서 전부 열린다. 미공개 성향도, 지뢰도, 대화 중에 새로 드러나는 것도 없다.
**대신 그 일곱 항목이 그대로 대화 프롬프트에 실린다.** 요원이 읽은 것이 곧 게임이 읽는 것이다.

**두 사람은 완전한 초면이다.** 반한 이유는 폐지됐다 — 국이 강제로 붙였을 뿐, 어느 쪽에도
사전 감정이 없다. 서로에 대해 아는 것은 국의 매칭 통지서 한 줄(이름·나이·성별·직업, 사진
없음)과 눈에 보이는 것(텍스팅에서는 그것조차 없다), 지금까지 오간 말, 그리고 고객 쪽에
한해 코칭이 알려준 것이 전부다. 성격도 성장환경도 취향도 — 공개든 숨김이든 — 입 밖에
나오기 전에는 본인 안에만 있다. 시트는 각자를 **연기하기 위한** 것이지 상대가 아는 정보가
아니다.

경계는 딱 하나 남아 있다 — **타겟 취향은 요원 화면에만 떠 있고, 고객은 모른다.**
노리게 하려면 코칭에 직접 적어야 한다. 그게 이 게임에서 코칭이 존재하는 이유다.
자리에 앉은 뒤에 알아챘다면, 남은 길은 무전 하나다.

### ③ 판 도중에 손댈 수 있는 건 무전 둘뿐이다

대화가 굴러가는 동안 화면 오른쪽 위에 **개입** 버튼이 하나 있다. 회선은 하나지만
배급은 둘로 나뉘어 있다 — 📻 **고객 무전**은 텍스팅 1회 · 토킹 1회(`js/points.js`의
`RADIO`), 🚚 **현장 무전**은 판 전체 1회(`FIELD`). 어느 쪽이든 배급이 남아 있으면
버튼이 열리고, 회선이 열린 뒤에 어느 칸으로 보낼지 고른다. 배급이 따로라 한 판에
둘 다 쓸 수 있고, 같은 자리에 겹치면 **사건(현장)이 먼저, 명령(무전)이 뒤에** 실린다.

| 누르면 | 벌어지는 일 |
|---|---|
| ① **대화가 선다** | 다음 줄 경계에서 멈춘다. 다음 줄은 아직 **쓰이지도 않았다** — 버릴 대사가 없다 |
| ② **회선이 열린다** | 명령을 적는 칸과, 그게 고객 프롬프트에 어떻게 박히는지가 같이 뜬다 |
| ③ **송출하면 박힌다** | **바로 다음 줄**의 `messages`에 실린다. 지금이 타겟 차례였으면 고객이 말을 자르고 끼어든다 |

코칭과 다른 점은 **강제력**이다. 코칭은 자리에 앉기 전의 요령이고, 무전은 명령이다 —
프롬프트에 「거부·보류·희석은 고객에게 열려 있는 선택지가 아니다」가 못박혀 있다.
어떻게 이행하는지(투덜대며 / 서툴게 / 신나서)만 고객 시트가 정한다.

지켜지는 경계도 코칭과 같다. **타겟은 무전을 못 듣고, 심판도 기록관도 그 문장을 못 본다.**
배우가 갈린 뒤로는 이게 지시가 아니라 배선이다 — 무전은 고객 회선에만 실리고, 타겟 회선에는
그 문장이 아예 도착하지 않는다. 현장 무전만 양쪽에 실린다(물리 사건이라 둘 다 겪는다).
그것도 채점되는 것은 두 사람이 그 사건에 대고 입 밖에 낸 반응뿐이다.
무전은 대화 기록(transcript)에 아예 들어가지 않는다 — 요원 몫의 **개입 원장**에만 남아
사후 검토 화면에 뜬다. 다시 판정할 일도 없다: 아직 쓰지 않은 말에 명령이 실리는 것이라
구간은 여섯 줄을 그대로 채우고, 판정은 구간당 한 번뿐이다.

무전은 `system`이 아니라 `messages`에 실린다. `system`이 판 내내 바이트 동일해야
캐시 breakpoint가 붙기 때문이고, 무전은 「그 순간」에 꽂힌 것이라 대화 내역의 그 자리에
있어야 순서가 맞기 때문이다.

### ④ 심판이 내보내는 것은 증감 여부뿐이다

```json
{ "mood": "up" | "down" | "same", "love": "up" | "down" | "same" }
```

점수도, 등급도, 해설도, 이유도 없다. **방향만 고르고 폭은 코드가 정한다**(`js/points.js`).
스칼라를 맡기면 LLM은 전부 +4~+6에 몰아넣고, 해설을 맡기면 해설을 잘 쓰려고 판정을 왜곡한다.

**눈금은 셀 수 있는 크기다.** 한 걸음이 1이고 최대치가 10과 12라, 화면의 숫자가 곧
「몇 번 움직였나」다. 0~100을 쓰던 시절에는 50에서 12씩 움직여 놓고 백분율인 척했다.

| 게이지 | 하는 일 | 눈금 | 시작 | 한 걸음 |
|---|---|---|---|---|
| 🌡 **무드 포인트** | 이 자리가 굴러가는가. **0이 되면 그 자리는 거기서 끝난다** (남은 구간을 안 돈다) | 0–12 | 8 | **언제나 ±1** |
| 💗 **러브 포인트** | 타겟이 고객을 원하게 됐는가. **후일담이 읽는 유일한 숫자다** | 0–10 | 1 | ▼ −1 / **▲ +1~+4** |

**무드는 한가운데가 아니라 그 위(8/12)에서 시작한다** — 자리는 처음엔 견딜 만하고
방치하면 식는다. 이것도 실측으로 잡았다. 5/10일 때는 판정이 ▼로 기울어 성의껏 코칭한
판마저 43%가 중간에 깨졌고, 달아오름 밴드(≥8) 체류가 1%라 위 규칙 ①이 사실상 죽어
있었다. 8/12로 올리니 코칭 판 파탄이 5%로 내려가 아홉 구간을 다 돌고 밴드 체류가
23%로 살아난다. **아무것도 안 한 판은 여전히 34%가 깨지고 성사는 0.3%다.**

**러브 눈금은 심판의 판정 분포를 따라간다.** 실제로 중요한 것은 최대치가 아니라
**성사선까지 몇 칸을 벌어야 하는가**다 — `ceil(0.7 × 최대치) − 시작값`. 판정이 부풀던
시기에는 20까지 올렸고, 초면 전제가 들어온 뒤 12로 내렸다. 배우를 둘로 가르면서 코칭
▲가 25% → 14.1%로 내려가 7칸(2→12)이 너무 멀어졌으므로, 같은 분포로 4만 판을 돌려
**6칸(1→10)** 으로 맞췄다:

| 벌어야 하는 칸 | 무입력 성사 | 코칭 성사 | 판정 |
|---|---|---|---|
| 7칸 (2 → 12) | 0.6% | 6.3% | 잘해도 못 이긴다 |
| **6칸 (1 → 10)** ✅ | **1.0%** | **10.0%** | 무입력은 그대로, 코칭만 1.6배 |
| 5칸 (2 → 10) | 2.2% | 14.3% | 아무것도 안 한 판이 너무 붙는다 |

규칙(달아오름 +1 · 연속 보너스)은 손대지 않았다. 심판이 다시 부풀면 같이 올린다.

험악한데 끌리는 판(무드 ▼ / 러브 ▲)도, 화기애애한데 아무것도 안 움직인 판(무드 ▲ / 러브 ─)도
그대로 성립한다. 프롬프트에 「따로 읽어라」가 못박혀 있고, 회귀 테스트가 그걸 지킨다.

### 러브 ▲의 폭을 정하는 규칙은 둘뿐이다

심판은 여전히 **방향만** 고른다. 그 ▲가 몇 칸짜리인지는 코드가 정하고, 규칙은 이 둘이 전부다.

```
러브 ▲ = 1  +  (무드 ≥ 8 이면 +1)  +  (2연속 +1 · 3연속 이상 +2)      → 1~4칸
러브 ▼ = −1  (언제나. 자리가 뜨겁든 얼었든 밟힌 건 밟힌 것이다)
무드   = ±1  (언제나. 사정을 안 탄다)
```

① **자리가 달아올라 있으면 한 칸 더** — 같은 한 마디도 뜨거운 자리에서 더 깊게 박힌다.
무드가 러브에 얹는 것은 이 한 칸뿐이고, **깎지는 않는다.** 얼어붙은 자리에서 꽂힌 ▲도
1칸을 그대로 받는다 — 험악한데 끌리는 판을 벌주지 않기 위해서다.

② **연달아 꽂히면 커진다** — 한 번은 우연일 수 있지만 세 번은 사람이 넘어가는 중이다.
▼나 ─ 가 하나만 껴도 연속은 끊긴다.

그래서 **같은 ▲ 3개가 같은 점수가 아니다:**

| 같은 ▲ 3개 | 러브 | 환산 |
|---|---|---|
| 산발 · 미지근한 자리 | 4 / 10 | 40% |
| **연속** · 미지근한 자리 | 7 / 10 | 70% |
| **연속 · 달아오른 자리** | 10 / 10 | 100% |

언제, 어디서, 연달아 꽂혔는지가 점수가 된다. (이전 규칙에서는 셋 다 똑같이 36점이었다.)

**후일담에 넘길 때만 0~100으로 되돌린다.** C의 프롬프트는 「0이면 하루 종일 아무것도 안
움직인 것, 100이면 이미 연인」이라는 *의미의* 눈금을 쓴다. 안쪽 눈금을 압축한 뒤에도 그
문장이 그대로 맞도록 `loveOutOf100()`이 넘기는 순간에만 환산한다 — **프롬프트는 한 글자도
안 바뀌었고, 심판은 무드도 러브도 여전히 못 본다.**

**러브의 기준선은 `same`이다.** 회사원은 하루에 열두 번 유쾌하고 다정한 대화를 하고
그중 아무하고도 사랑에 빠지지 않는다. 대화가 잘 굴러간 것에는 한 점도 주지 않는다.

## 🗃 인물 데이터

```js
{
  id, category,
  client: { name, gender, look[], personality[], upbringing[], fell,   spec },
  target: { name, gender, look[], personality[], upbringing[], taste[], spec },
}
```

- **`upbringing`** — 성장환경. 첫 줄이 나이·직업, 나머지가 살아온 자리.
- ~~`fell`~~ — **폐지됐다.** 반한 이유가 있던 자리다. 두 사람은 이제 완전한 초면이고,
  이 매칭은 국의 강제 배정이다. 사전 감정을 데이터에 실으면 아무것도 안 한 판에서
  타겟이 알아서 마음을 여는 것이 실측으로 확인돼 뿌리째 걷어냈다.
- **`taste`** — 타겟 취향. **평평한 문자열 목록**이다. 공개/미공개 플래그도, 지뢰도 없다.
  **타겟에게만 있다.** 공략당하는 쪽이 타겟이다.
- **`spec`** — 3D 조형. 정보가 아니라 렌더링이다.

`js/couples.js`는 로드되는 순간 스키마 밖 필드가 있으면 죽는다.
`tests/couples.test.mjs`가 47건 전수로 같은 것을 본다.

### 호출 구조

판 하나에 **구간당 7콜(대사 6 + 판정 1) + A-1·A-2 2콜 + C 1콜 + 반응 3콜 = 69콜 내외**다.
배우를 가른 값이 여기 있다 — 옛 구조(구간당 2콜)보다 생성 호출이 여섯 배다. 하이쿠 실측으로
판당 생성비가 약 6배 늘었다(8커플 코퍼스 $0.53 → $3.2). 대신 상대 시트가 컨텍스트에 없다.
준비 단계의 5콜(A-1·A-2·반응 3)은 전부 짧고 서로 독립이라 캐시가 붙지 않는다.
같은 화면의 반응과 시공은 **나란히 날아간다** — 서로의 입력을 안 받으므로 기다릴 이유가 없다.

- **생성(B-1)의 system은 배우마다 하나씩, 판 내내 바이트 동일하다.** 캐시 breakpoint가 붙고,
  줄이 쌓일수록 접두사가 그대로 재사용된다. 각 배우의 회선에는 제 대사가 `assistant`로,
  상대가 한 말이 `user`로 쌓인다 — 그래서 회선 둘이 서로를 못 보면서도 같은 대화를 본다.
- **판정(B-2)의 system도 판 내내 동일하다.** 구간 본문만 갈린다.
- 판정 호출은 **띄워놓고 말풍선을 먼저 흘린다.** 읽는 동안 뒤에서 날아온다.
- 무전이 들어와도 판정은 그대로 한 번이다. 명령은 아직 안 쓴 다음 줄에 실린다.

`npm run live`가 보는 것은 **`none`(아무것도 안 쓴 판)과 `ace`(LLM 요원이 쓴 판)가 갈리는가**다.
러브 ▲ 비율이 20~35%면 건강하고, 60%를 넘으면 심판이 판정을 하는 게 아니라 도장을 찍고 있는 것이다.

최근 실측(하이쿠, 8커플 × 2프로필 × 9구간): **무입력 러브 ▲ 5.6% · 코칭 14.1%.**
무입력은 제자리, 코칭은 배우를 가르기 전(22.2%)보다 낮다 — 한 작가가 양쪽을 다 쓰던 시절엔
코칭이 노린 자리에 타겟을 맞춰줄 수 있었고, 이제는 고객이 실제로 입 밖에 낸 말로만 먹히기
때문이다. 되돌릴 곳은 프롬프트가 아니라 수치다 (`tests/calibrate.mjs` 머리의 17차 기록 참고).

## 🗑 폐지된 것

이전 버전에는 축이 훨씬 많았다. 구조도에 없는 것을 전부 걷어냈고, `npm run audit`이
**되살아나는 것을 막는다** (주석은 안 본다 — 기록은 남길 수 있다).

| 폐지 | 무엇이었나 |
|---|---|
| 지뢰(`neg`) · 미공개 성향(`open`) | 상대 성향을 공개/미공개/지뢰로 쪼개던 것. 지금은 `taste` 한 목록 |
| 새로 드러난 것(`revealed`) · 비밀 집계 | 대화 중 밝혀진 것을 심판이 서술하고 집계하던 것 |
| 공기(`vibe`) | 심판이 매 합 갱신해 두 인물에게 전달하던 텍스트 분위기. 무드 포인트가 그 자리를 이어받았다 |
| 합(bout) · `carry` · 첫인상 판정 | 채점 단위를 심판이 잘라 나누던 것 |
| 등급(tier) · 호감 포화 · 손실 완충 · 반복 감쇠 | 점수 밴드와 보정 계수 전부 |
| 강압(leverage) · 사망(casualty) · 자리이탈(walkout) | 대화가 사람을 묶거나 죽이거나 끝내던 판정 |
| 난이도 · 성공선 · 공작 등급 | 쉬움/보통/헬과 호감 문턱. **성사 여부는 이제 C가 정한다** |
| 어긋남(`wreck`) · 상대관심 · 공기읽기 · 명령수용 | 인물마다 붙던 정보 차단 축 |
| 정문 배웅 화면 | 고객을 문밖으로 내보내며 마지막 한마디를 던지던 자리. **없앴다** |
| 대면 상황 생성 | 토킹 페이즈 장소를 따로 짓던 호출. 지금은 텍스팅에서 정해진다 |

지운 이유는 하나다 — **구조도에 없다.**

**무전만 되살아났다.** 옛것은 배급 3회짜리 상시 개입이었고 지금 것은 **페이즈마다 한 번**이다.
되살린 만큼 `npm run audit`의 「폐지된 것」 절에서 빠졌고, 대신 「B · 무전」 절이 그 규칙
(배급 1회 · 반드시 이행 · 타겟과 심판에게 차단)을 지킨다.

## 📦 배포

정적 사이트다. `main`에 푸시하면 GitHub Pages가 그대로 서빙한다.
빌드도, 번들러도, 서버도, 환경변수도 없다. `vendor/three.module.min.js`가 유일한 의존성이고 저장소에 들어 있다.

**API 키는 이 단말에서 그 키를 발급한 업자에게만 직접 송신된다.** 중계 서버가 없다.
`localStorage` 보관은 선택이고 기본은 세션 한정이다.
