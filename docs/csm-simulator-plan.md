# 🎖 무사고 100일: 주임원사 — 기획서

> 만년상사. 이번이 마지막 진급 기회다. **무사고 100일**을 찍으면 원사 진급.
> 사고가 터지면 카운터는 0으로 돌아간다. 병사들은 그대로 남아서, 당신을 지켜본다.

연애조작단 2077(이 저장소)과 같은 문법으로 만든다 — **한 장의 구조도가 곧 게임**이고,
구조도에 없는 것은 게임에 없다. 서버 없음, 빌드 없음, GitHub Pages에서 그대로 돈다.
`js/llm.js`(업자 판별·캐시·재시도·구조화 출력)는 그대로 재사용한다.

---

## 1. 개요

| 항목 | 내용 |
|---|---|
| 장르 | LLM 텍스트 부대 운영 시뮬레이터 (일일 턴제) |
| 주인공 | 어떤 부대의 **주임원사**. 만년상사, 마지막 진급 기회 |
| 승리 조건 | **무사고 연속 100일** — 달성 시 원사 진급 엔딩 |
| 패배 조건 | 없다. 사고가 터지면 무사고 카운터만 0으로 회귀. 임기 제한 없음 |
| 날짜 | **현실 날짜 그대로 기입한다.** 부임일 = 플레이 시작한 현실의 오늘 − 100일 |
| 부대 선택 | 게임 시작 시 3개 군 중 택1로 부임. 현재 구현 대상은 **해병 성채 · 공군 체계단** 둘 |

### 날짜 규칙

부임하는 순간 `startDate = 현실 오늘 − 100일`로 박힌다. 게임 1턴 = 달력 1일.
달력은 언제나 전진하고, 사고가 나면 **무사고 카운터만** 0이 된다 — 날짜는 안 돌아간다.

- 한 번도 안 터뜨린 완주는 정확히 **현실의 오늘**에 진급 심사를 맞는다. 그게 이 규칙의 맛이다.
- 터뜨리면 진급 심사일이 오늘을 지나 미래 날짜로 밀린다. 화면의 날짜가 그걸 그대로 보여준다.
- 계절·요일은 날짜에서 계산한다(코드). 여름 혹서기 통제, 겨울 제설, 주말 일과 없음 —
  전부 달력이 정하는 static 입력이고, 일과 난이도와 사건 후보 풀에 반영된다.

## 2. 군 선택 — 부대 프롬프트

군마다 다른 것은 단 하나, **부대 프롬프트**다. 이 텍스트 덩어리가 병사의 생활을 뽑아내는
엔진의 재료로 들어가고, 신규 전입 병사의 프로필을 뽑을 때도 들어간다. 다섯 절로 구성된다.

| 절 | 내용 | 성격 |
|---|---|---|
| ① 문화 | 핵심가치·군 역사·분위기. 창설 서사, 전용 용어(딸수·짬찌·찐빠 등), 복식, 복무기간 | 텍스트 |
| ② 규정 | 출타 시간, 폰 사용 시간, 태블릿 허용 여부, 실외 탈모 금지 등 기본 군 규정 | 텍스트 |
| ③ 병사간 룰 | 일병 이하 사지방 금지, BX 금지 같은 자체 룰(부조리의 씨앗) | 텍스트 |
| ④ 지능 | 병사 모집단의 지능. **수치(0~10) + 서술** 한 쌍 | 텍스트+수치 |
| ⑤ 마초 | 병사 모집단의 마초력. **수치(0~10) + 서술** 한 쌍 | 텍스트+수치 |

④·⑤가 수치를 함께 드는 이유: **서술은 프롬프트로, 수치는 코드로** 간다. 지능·마초는
생성 텍스트의 말투를 정하는 동시에 사고 확률 공식(§4)의 입력이다. 같은 원천에서 한 번만 정의한다.

### 부대 둘 (초기 데이터 스케치)

```
해병 성채 — 서해 최전방 도서 방어 대대
  ① 귀신 잡는 전통, 기수 문화, 상륙 서사. 용어: 딸녀, 악기바리, 돌격
     복무기간 18개월, 팔각모·상륙돌격형 두발
  ② 출타 통제 빡빡, 폰 사용 평일 저녁 한정, 태블릿 불허, 실외 탈모 금지
  ③ 이병은 BX 이용 금지, 일병 이하 사지방 주말 한정, 기수 열외 문화 잔존
  ④ 지능 4 — "머리보다 몸이 먼저 나간다"
  ⑤ 마초 9 — "다치는 걸 자랑으로 아는 놈들"
  일과 난이도 8 (해안 경계 + 진지 공사)

공군 체계단 — 후방 정보체계 관리 부대
  ① 신사적 분위기, 창설 이래 무사고 전통 자부심. 용어: 딸수, 짬찌, 찐빠
     복무기간 21개월, 약모, 전투복보다 근무복
  ② 출타 자유로운 편, 폰 사용 일과 후 상시, 태블릿 허용, 두발 규정 느슨
  ③ 병사간 룰 거의 없음 — 대신 은근한 따돌림형 부조리가 취약점
  ④ 지능 8 — "수능 다시 보러 온 것 같은 놈들"
  ⑤ 마초 2 — "체력 검정이 최대 위기"
  일과 난이도 3 (서버 점검 + 문서 작업)
```

부대 프롬프트는 `js/units.js`에 산다(연애조작단의 `couples.js` 포지션 — 로드 시 스키마 검증,
스키마 밖 필드가 있으면 죽는다). 세 번째 군은 이 파일에 항목 하나를 더하는 것으로 끝나야 한다.
**코드 어디에도 특정 부대를 아는 분기를 두지 않는다.**

## 3. 병사

부대 프롬프트로 생성된 병사들이 있다. 프로필은 다섯 필드다.

```js
{
  name,        // 이름
  serial,      // 군번 — 군별 형식으로 코드가 채번
  job,         // 직무 (부대 프롬프트의 직무 슬롯에서 배정)
  grade,       // 폐급 ~ 에이스 (5단계: 폐급·C·B·A·에이스)
  character,   // 인성 등급 (5단계)
  sheet,       // LLM이 쓴 프로필 본문 — 성격·배경·말버릇·군생활 태도 (🟫 cached)
  joined,      // 전입일 (현실 날짜)
}
```

- **등급 둘은 코드가 굴린다.** 지능이 높은 부대일수록 에이스 확률이, 마초가 높을수록
  폐급·인성 하위 확률이 올라가는 가중 추첨(`js/params.js`). LLM은 굴려진 등급에 **맞는
  인물을 쓰는 일**만 한다. 등급을 LLM에 맡기면 전원이 B급 무난한 인물로 수렴한다 —
  연애조작단에서 스칼라를 심판에 맡겼을 때와 같은 병이다.
- **병사별 대사는 병사별 프로필을 통해 나온다.** 면담·사건·반응, 병사가 입을 여는 모든
  호출에 그 병사의 sheet가 실린다. 만들어진 병사는 `localStorage`에 저장되어 재사용된다.
- 정원 16명. 복무기간(부대 프롬프트 ①)이 차면 전역하고, 빈 자리에 전입이 온다(P 호출).
- **사고로 카운터가 리셋되어도 병사 데이터와 파라미터는 유지된다.** 어제 싸운 두 놈은
  0일차에도 여전히 서로를 노려보고 있다.

## 4. 부대 파라미터 — 전부 코드가 든다

구조도에서 검은 칸(⬛ code)에 해당하는 것들. `js/params.js`에 살고, LLM 없이 단독 테스트된다.
눈금은 연애조작단 규칙 그대로 — **0~10, 한 걸음 1칸.** 화면의 숫자가 곧 「몇 번 움직였나」다.

| 파라미터 | 무엇인가 | 움직이는 법 |
|---|---|---|
| 🏋 일과 난이도 | 일이 얼마나 힘든가 | **static.** 부대 프롬프트가 정하고 계절 보정만 받는다. 주임원사가 못 건드린다 |
| 📋 가라 | 일을 얼마나 대충 하는가 (FM의 반대말) | 공지·사건 결과의 방향 판정 ±1 |
| 😊 행복도 | 분위기와 사실상 동의어 | 방향 판정 ±1 + 일일 드리프트 |
| ⚡ 갈등·부조리 | 병사 사이의 억압과 서열 | 방향 판정 ±1 + 일일 드리프트 |
| 🎖 평판 | 주임원사에 대한 병사들의 우호도 | **LLM이 안 건드린다.** 개입(면담·점검·공지)마다 −1, 조용한 날 +1 회복 |

### 파라미터끼리 이렇게 얽힌다 (전부 코드 공식)

- **일과 난이도↑** → 행복도 드리프트↓, 갈등 드리프트↓ (힘들면 싸울 기력도 없다).
  난이도가 높은데 **가라도 높으면** 사고 위험이 급증한다 — 힘든 일을 대충 하면 다친다.
- **가라↑** → 행복도 드리프트↑ (편하니까). 대신 검열·감사 계열 사건에서 위험 가중.
  가라가 높은데 **지능이 낮으면** 사고 위험 가중 — 알아서 잘 대충 할 머리가 없다.
- **가라↓** → 행복도 드리프트↓ — FM대로 굴리면 병사들이 힘들어한다.
- **행복도↑** → 갈등 발생 확률↓.
- **갈등·부조리↑** → 작은 사고 확률↓ (군기가 눌러 놓는다), 행복도 드리프트↓.
  **8을 넘기면 큰 사고(탈영·자해 등) 전용 위험이 열린다.** 눌러 놓은 게 터질 땐 크게 터진다.
- **평판↑** → 공지 이행률·면담 솔직도 등급이 올라간다(§6의 코드→프롬프트 입력).
  덜 간섭할수록 병사들이 말을 잘 듣는다.

### 사고 판정 롤 (LLM 없음)

하루 9개 일과 슬롯(§5)마다 코드가 한 번씩 굴린다.

```
작은사건 위험 = 기본치
             + 마초 가중
             + max(0, 가라 + 난이도 − 10)      // 힘든 일 + 대충
             + max(0, 가라 − 지능)              // 대충할 머리가 안 됨
             − 갈등 억제분                       // 눌려 있으면 잔사고가 준다
큰사건 위험   = (갈등·부조리 ≥ 8 이면) 초과분 × 가중   // 탈영·자해·집단 사고 풀
```

롤이 성공하면 **사건**이 발생한다. 사건은 아직 사고가 아니다 — §5의 대응 루프를 거쳐
`확전`으로 판정될 때만 **사고**가 되고, 그때만 카운터가 0으로 돌아간다.
잘 막은 사건은 무사고 판정이다. 용어를 못박는다:

> **사건** = 발생한 상황. **사고** = 대응에 실패해 커진 사건. 카운터를 리셋하는 것은 사고뿐이다.

수치·확률·가중치의 실값은 전부 `js/params.js` 상수 하나에 모으고, 밸런싱은 그 파일만 만진다.

## 5. 게임 루프 — 하루가 한 턴

### 일과 타임라인 (화면)

해가 움직이고 배경색이 바뀌며, 작은 사람 스프라이트 판때기들이 식당·생활관·사무실을
왔다갔다한다(three.js 빌보드 — `avatar.js`의 저렴한 친척). 슬롯은 아홉이다.

```
아침점호 → 아침식사 → 오전일과 → 점심식사 → 오후일과 → 저녁식사 → 하번 후 휴식 → 저녁점호 → 수면
```

수면이 끝나면 다음 날 아침점호로 돌아온다 — 턴 종료·개시. 슬롯마다 사고 판정 롤이 돈다.
사건이 발생한 병사 스프라이트 위에는 ❗가 뜨고, 달려가면(클릭) 사건 화면이 열린다.

### 턴 구조

1. **아침 브리핑** — 일과 시작 전, 부대 현 상황 정보가 주어진다(D 호출). 어제의 사건 결과,
   전입·전역, 오늘 일정, 그리고 **증상들** — 파라미터 수치가 아니라 병사들 사이에서 관찰되는
   낌새다. "요즘 3생활관이 조용합니다"가 행복도 폭락의 신호일 수 있다. 읽는 눈이 실력이다.
2. **일과 시작**을 누르면 해가 뜬다. 일과 중 주임원사가 할 수 있는 일은 셋:
   - 🗣 **면담** — 병사를 지정해 불러다 이야기한다(I-1 호출). 그 병사가 아는 것을 들을 수
     있지만, 불려간 놈 입장이 있다. **평판 −1.**
   - 🔦 **불시점검** — 장소(생활관·사무실·창고…)를 지정해 들이닥친다(I-2 호출). 그 장소가
     드러내는 파라미터 밴드를 직접 본다. **평판 −1.**
   - 📢 **공지** — 아무 때나 병영생활 지침을 올린다(N 호출). 텍스트는 활성 지침 목록에
     들어가 이후 모든 생활·사건 생성에 주입되고, 파라미터를 방향으로 움직인다. **평판 −1.**
3. **사건 대응** — 사건이 발생하면 달려가서 텍스트로 지침을 내리고(E 호출 셋) 결과를 본다.
   무시하고 일과를 계속 볼 수도 있다 — 그 경우 '개입 없음'으로 결과가 굴러간다. 축구 중 부상,
   점호 인원 빔(탈영 의심), 미상번 후 구석에 짱박혀 수면 — 가볍고 무거운 후보가 코드의
   사건 풀에 살고, 심각도 티어와 함께 뽑힌다.
4. **하루 마감** — 저녁점호가 끝나면 드리프트가 적용되고 카운터가 +1. 지침도 안 내리고
   사건도 없는 날도 있다 — 그런 날은 브리핑 한 콜로 하루가 끝난다. 조용한 날이 제일 싼 날이다.

### 이 게임의 셈법

가라를 최대한 높게 유지해 행복도를 챙기되 사고 위험 가중(난이도·지능과의 곱)을 넘지 않는 선을
찾는 것, 갈등·부조리를 적당히 두면 잔사고가 줄지만 방치하면 탈영이 터진다는 것, 정보를 보려면
평판을 내야 하는데 평판이 낮으면 지침이 안 먹힌다는 것 — 세 개의 저울이 이 게임의 전부다.

## 6. 프롬프트 하이어아키 — 이 문서의 심장

범례는 연애조작단과 동일하다. **색이 곧 데이터의 출처다.**

| 색 | 뜻 | 이 게임에서 |
|---|---|---|
| 🟩 **static** | 테이블로부터의 static 데이터 | 부대 프롬프트 5절 · 계절/일정 · 사건 풀 |
| 🟦 **user** | 유저 인풋 (모두 캐시됨) | 공지(활성 지침) · 면담 질문 · 사건 대응 지침 |
| 🟫 **cached** | 캐시되는 LLM 생성 텍스트 | 병사 프로필 sheet |
| 🟧 **once** | 일회성 LLM 생성 텍스트 | 브리핑 · 사건/결과 장면 · 면담 대사 · 점검 소견 |
| ⬛ **code** | 코드용 분류 | 파라미터 5종 · 등급 굴림 · 사고 롤 · 확전 판정 결과 · 카운터/날짜 |

**숨은 파라미터는 프롬프트에 수치로 들어가지 않는다.** 코드가 0~10을 5단계 밴드
(`very-low … very-high`)로 낮춰서만 건넨다. 수치가 프롬프트 문자열에 새면 테스트가 깨진다(§9).

### 블록은 일곱이다

```
U. 부대 프롬프트                          (호출이 아니라 재료 — 모든 생성 호출의 system 접두사)
     [static] ①문화 ②규정 ③병사간 룰 ④지능 서술 ⑤마초 서술
     ④⑤의 수치는 여기 없다 — 그건 ⬛로 params.js에 산다

P. 전입 병사 생성                                        (전입 때만)
     [static] 부대 프롬프트
   + [code]   굴려진 등급 (폐급~에이스 · 인성) + 직무 슬롯 + 군번
   → [cached] 병사 프로필 sheet — 저장되고, 그 병사가 입을 여는 모든 호출에 실린다

D. 아침 브리핑                                           (매일 1회)
     [static] 부대 프롬프트 + 오늘 일정·계절
   + [code]   파라미터 **밴드** + 어제 사건 결과 요약 + 전입·전역
   + [cached] 명부 발췌 (오늘 등장할 병사들)
   → [once]   브리핑 텍스트 + 일과 중 슬롯마다 흘릴 일상 조각 대사들
              ("수치를 말하지 말라. 증상으로만 말하라"가 지시문에 박힌다)

E-1. 사건 장면                                           (사고 롤 성공 시)
     [static] 부대 프롬프트 + [code] 슬롯·장소·심각도 티어 + 연루 병사 선정(등급 가중)
   + [cached] 연루 병사 프로필 + [user] 활성 지침 목록
   → [once]   사건 장면 텍스트

E-2. 대응 결과
     [once]   사건 장면 + [user] 그 자리에서 내린 지침 (없으면 "개입 없음")
   + [cached] 연루 병사 프로필 + [code] 평판 밴드 (지침이 먹히는 정도)
   → [once]   결과 장면 텍스트

E-3. 확전 판정 — **지침을 못 본다**
     [once]   결과 장면 + [code] 심각도 티어
   → [code]   { outcome: "contained" | "escalated",
                gara: up|down|same, happy: up|down|same, conflict: up|down|same }

I-1. 면담 — **파라미터를 못 본다**
     [static] 부대 프롬프트 + [cached] 그 병사 프로필
   + [code]   그 병사의 체감 밴드 (자기 주변 것만) + 솔직도 등급 (평판에서 계산)
   + [user]   주임원사의 질문
   → [once]   병사의 대사 — 몇 회 왕복 가능, 스레드는 그 면담에서 닫힌다

I-2. 불시점검 — 병사 입이 아니라 눈으로 본다
     [static] 부대 프롬프트 + [code] 점검 장소 + **그 장소가 드러내는 파라미터의** 밴드
   → [once]   점검 소견 텍스트 (생활관은 갈등을, 작업장은 가라를 드러낸다 — 장소-파라미터
              대응표는 코드에 산다)

N. 공지 판정 — 게시는 저장이고, 판정은 방향뿐이다
     [user]   공지 원문 + [static] 부대 프롬프트
   → [code]   { gara: up|down|same, happy: up|down|same, conflict: up|down|same }
   + [once]   익명 병사 반응 한 줄 — 화면에 뜨고 거기서 끝난다 (연애조작단의 R.
              데이터가 아니라 소리다. 어떤 호출에도 재입력되지 않는다)
```

### 정보 차단 규칙 — 누가 뭘 못 보는가

연애조작단의 「미용실은 성격을 못 보고, 취조실은 외모를 못 본다」에 해당하는 선들.
**이 표가 곧 회귀 테스트다** (§9).

| 호출 | 못 보는 것 | 이유 |
|---|---|---|
| E-3 확전 판정 | 주임원사의 **지침 원문** | 지시가 보이면 심판은 실제로 벌어진 일 대신 지시의 영리함을 채점한다. 심판이 읽는 것은 결과 장면뿐 |
| E-3 · N 판정 | 파라미터 현재값 (밴드조차) | 현재값을 보면 "이미 높으니 same"식 자기참조 판정을 한다. 방향은 사건·공지 그 자체에서만 |
| I-1 면담 | 부대 전체 파라미터 | 병사는 부대 지표를 모른다. 자기 생활관, 자기 일 — 자기 체감만 안다 |
| P 병사 생성 | 현재 파라미터·명부 | 전입자는 부대 상태와 무관하게 온다. 등급은 굴림이 정했고, LLM은 인물만 쓴다 |
| D 브리핑 | 파라미터 **수치** | 밴드까지만. 그마저 증상으로 바꿔 말하라는 지시가 붙는다 |
| 전 호출 공통 | 무사고 카운터·사고 확률·굴림 결과 | 메타 정보다. 병사도 브리핑도 "오늘 87일차라 조심하자" 같은 말을 하면 안 된다 |
| 평판 | **어떤 LLM 판정도 평판을 못 움직인다** | 개입 횟수가 곧 평판이다. 순수 코드 |

### 주임원사가 쓴 글은 채점되지 않는다

연애조작단 규칙 ①의 계승. 공지·면담 질문·사건 지침 — 셋 다 점수가 없다. 문장은 프롬프트에
**그대로 주입**되고, 판정되는 것은 오직 **"그래서 부대에서 실제로 무슨 일이 벌어졌는가"**(결과
장면)뿐이다. 시험이 아니라 프롬프팅이다.

### 지시는 영어, 출력은 한국어

연애조작단 규칙 그대로. 프롬프트 지시문은 전부 영어. 한국어는 (1) 부대 프롬프트·병사
데이터, (2) 화면 라벨, (3) 한국어 출력 예시 — 셋뿐이다. ASCII 가상 부대로 전 블록 프롬프트를
지어 한글이 한 글자라도 남으면 테스트가 깨진다.

## 7. LLM 콜 & 캐시 전략

### 하루의 콜 수

| 상황 | 콜 |
|---|---|
| 조용한 날 | **1** (D 브리핑) |
| 사건 1건 | +3 (E-1 · E-2 · E-3) |
| 공지 1건 | +1 (N — 판정과 반응을 한 호출의 한 스키마로 받는다) |
| 면담 1회 | +1~3 (왕복 수만큼) |
| 불시점검 | +1 |
| 전입 | +1 (P) |

보통의 하루는 **2~6콜**, 100일 완주는 300~500콜 규모다. 연애조작단이 판당 24콜이었으니
긴 게임인 만큼 하루를 싸게 유지하는 것이 생존 조건이고, 그래서 아래 캐시 설계가 본체다.

### system 접두사 — 부임 내내 바이트 동일

모든 **생성 계열** 호출(D·E-1·E-2·I-1·I-2·P)의 system은 같은 순서로 조립한다:

```
[WORLD: 톤·언어·수위 — 전 부대 공통, 리터럴]  ← 바이트 동일
[UNIT: 부대 프롬프트 5절 — 부임 시 확정]        ← 바이트 동일 (부임 내내)
[ROLE: 블록별 지시문 — 리터럴]                  ← 블록별로 바이트 동일
```

공통 접두사(WORLD+UNIT)가 가장 크고 가장 안 바뀐다. 캐시 breakpoint는 `llm.js`가 이미
하듯 system 블록과 마지막 user 메시지에 건다. **가변 데이터(밴드·명부·지침 목록)는 절대
system에 넣지 않는다** — 한 글자만 갈려도 접두사 캐시가 통째로 깨진다. 전부 user 메시지로.

### 하루 한 스레드

D·E-1·E-2는 **같은 대화 스레드**를 공유한다(system 동일). 아침 브리핑이 첫 user/assistant
쌍이 되고, 사건이 터질 때마다 messages에 쌓인다 — 오전의 사건 맥락을 오후의 사건이 공짜로
안다(연애조작단 B-1이 대화 내역을 평문으로 쌓는 것과 같은 수법). 스레드는 하루가 끝나면 닫고,
다음 날은 어제의 **코드 요약**(⬛ → D의 입력)으로 시작한다. 100일치 원문을 끌고 다니지 않는다.

- 면담(I-1)은 별도 단명 스레드 — 그 면담 안에서만 왕복하고 닫는다.
- 판정(E-3·N)은 스레드가 없다. system은 부임 내내 바이트 동일, user 한 장, 스키마 출력.

### 모델 배정 (`llm.call({model})` 재사용)

| 호출 | 모델 | effort |
|---|---|---|
| D · E-1 · E-2 · I-1 · P | 표준 (본부 권장) | low |
| E-3 · N · I-2 | **저가 모델** | low |

판정은 기계적이고 스키마가 좁다 — 연애조작단이 심판을 싸게 돌리는 자리와 같다.
판정 호출은 **띄워놓고 결과 장면 텍스트를 먼저 흘린다.** 읽는 동안 뒤에서 날아온다.

### 구조화 출력

E-3·N은 enum만 있는 좁은 JSON 스키마(위 블록도의 형태 그대로). 방향 밖의 어떤 필드도 없다 —
점수도, 해설도, 이유도 없다. **방향만 고르고 폭은 코드가 정한다.** P는 프로필 필드 스키마,
D는 `{ briefing, slots: [...] }` 스키마로 받는다. 스키마 키워드는 `llm.js`의
`stripUnsupportedSchemaKeys` 부분집합만 쓴다.

## 9. 테스트 — 하이어아키가 곧 회귀 테스트

`tests/orders.test.mjs`의 수법을 그대로 옮긴다:

1. **표식 주입 전수 검사** — 필드마다 표식을 심은 가상 부대·가상 병사로 일곱 블록의
   프롬프트를 만들고, §6의 차단 표를 전수 확인한다. 확전 판정 프롬프트에 지침 표식이
   보이면 실패. 면담 프롬프트에 부대 파라미터 표식이 보이면 실패.
2. **수치 누출 검사** — 숨은 파라미터의 **원수치**가 어떤 프롬프트 문자열에도 나타나지
   않는다. 밴드 라벨만 허용.
3. **params 단독 테스트** — 드리프트·사고 롤·등급 추첨·확전 처리 전부 LLM 없이.
   특히: 갈등 8 초과에서만 큰 사건 위험이 열리는가, 평판이 개입 횟수만으로 움직이는가,
   사고 후 카운터는 0인데 파라미터·명부는 그대로인가.
4. **한글 누출 검사** — ASCII 가상 부대로 전 블록을 지어 지시문에 한글이 남으면 실패.
5. **가짜 LLM 브라우저 E2E** — 결정적 LLM 대체로 하루 3턴: 브리핑 → 사건 → 대응 →
   확전(리셋) → 다음날 브리핑에 어제가 요약되는가. 키도 크레딧도 필요 없다.
6. **live 분포 검사** (`npm run live`) — 실제 API로 같은 사건에 「모범 지침 / 개입 없음」
   두 갈래를 돌려 확전율이 갈리는가. 무대응 확전율이 지침 확전율과 같다면 심판이 판정을
   하는 게 아니라 도장을 찍고 있는 것이다.

## 10. 만들지 않는 것

처음부터 선을 긋는다. 구조도에 없는 것은 게임에 없고, `npm run audit`이 되살아나는 것을 막는다.

| 안 만든다 | 왜 |
|---|---|
| 간부 NPC·지휘관 결재 라인 | 축이 하나 는다. 주임원사와 병사들, 둘뿐이다 |
| 병사별 개별 호감도/스탯 | 부대 파라미터 5종과 프로필 등급 2종으로 끝. 스칼라를 늘리지 않는다 |
| LLM이 정하는 파라미터 폭·확률 | 방향만. 폭과 굴림은 전부 `params.js` |
| 사건 자동 생성(풀 밖 창작) | 사건 후보와 심각도는 코드의 풀에서 뽑는다. LLM은 장면만 쓴다 |
| 실시간 진행·슬롯 강제 대기 | 타임라인은 연출이다. 스킵 가능해야 한다 |
| 서버·계정·랭킹 | 정적 사이트. 저장은 `localStorage` |
